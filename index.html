Featured Project 01 — Flagship Academic & Systems Project

NEMDS

National Centralized Emergency Medical Dispatch System

ASP.NET Core React MySQL / PostgreSQL REST API

“NEMDS is a software system designed to coordinate emergency medical requests between callers, dispatchers, hospitals, and ambulance drivers.” In a medical emergency, fragmented phone calls cause delay. NEMDS provides an organized backend workflow to track case states, log patient severity, assign ambulance units, and notify receiving hospitals.

System Dispatch Architecture Sequential Event Flow
CALLER → EMERGENCY REQUEST → BACKEND API → DISPATCHER → HOSPITAL → AMBULANCE → LIVE LOCATION

Backend Concepts Implemented & Addressed:

● REST API Routing
● Normalized Schema
● Role-Based Workflows
● Case State Machine
● GPS/Location Data
● Dispatcher Routing
● Ambulance Status
● JWT Auth Token
● DTO Validation
● Audit Logging
IMPLEMENTED IN CURRENT BUILD:
  • Relational emergency case schema & user role tables
  • ASP.NET Core REST endpoints for creating & fetching incidents
  • Dispatcher triage status transitions (Reported → Dispatched → Resolved)
  • React admin dashboard view for hospital capacity & triage records
PLANNED EXTENSIONS (IN PROGRESS):

VIEW FULL ENGINEERING CASE STUDY (7 SECTIONS) ▼
01 — Problem

Medical dispatch requires immediate coordination across callers, ambulances, and trauma wards. Manual phone coordination creates data silos, delayed response, and no centralized record of ambulance availability.

02 — System Design

Adopted a layered backend architecture using ASP.NET Core Web API. Dedicated Controllers parse HTTP requests, Service classes enforce triage validation, and repositories communicate with MySQL/PostgreSQL using strongly typed DTOs.

03 — Database Architecture

Normalized schema with tables: emergency_cases, ambulances, hospitals, users, and dispatch_logs. Foreign keys enforce integrity across dispatch assignments.

04 — API Specifications

POST /api/v1/cases — Create new emergency intake

GET /api/v1/cases/active — Dispatcher live backlog

PATCH /api/v1/cases/{id}/assign-unit — Lock ambulance to ticket

05 — User Roles

Role-based authorization distinguishing: Caller (creates ticket), Dispatcher (manages assignment), Ambulance Driver (updates en-route / arrived statuses), and Hospital Admin (bed availability).

06 — Engineering Challenges

Handling concurrent status updates without race conditions. If two dispatchers attempt to assign the same idle ambulance, database concurrency constraints must prevent double-booking.

07 — What I Learned

Designing clean domain models before writing code saves hours of refactoring. Structuring database transactions properly prevents inconsistent state when requests fail midway.
